## Project Overview

GeoRecords is an iOS SwiftUI app that tracks geographical records (furthest north, south, east, west, highest altitude, lowest altitude, and furthest from home). It runs continuously in the background, periodically checking location and updating records when new extremes are reached.

## Building and Testing

This is an Xcode project. You cannot use `xcodebuild` commands since Xcode is not installed (only Command Line Tools). The app must be built and run through Xcode IDE.

**Test Files:**
- `GeoRecordsAppTests/GeoRecordsAppTests.swift` - Unit tests (currently minimal)
- `GeoRecordsAppUITests/` - UI tests

## Core Architecture

### Manager Singletons (MVVM Pattern)

The app uses several singleton managers that serve as the source of truth:

1. **LocationManager** (`LocationManager.swift`)
   - Singleton: `LocationManager.shared`
   - Uses `startMonitoringSignificantLocationChanges()` for battery-efficient background tracking
   - Triggers location updates when device moves ~500 meters
   - Publishes `currentLocation: CLLocation?` for views
   - Automatically forwards location updates to `RecordManager.shared.updateRecords()`
   - Requests "Always" authorization and enables background location updates
   - Works indefinitely in background without requiring foreground activation

2. **RecordManager** (`RecordManager.swift`)
   - Singleton: `RecordManager.shared`
   - Maintains in-memory `@Published` properties for all current records across 3 timeframes (Monthly, Yearly, All-Time):
     - Monthly: `furthestNorthMonth`, `furthestSouthMonth`, etc.
     - Yearly: `furthestNorthYear`, `furthestSouthYear`, etc.
     - All-Time: `furthestNorthAllTime`, `furthestSouthAllTime`, etc.
   - Each record is a `RecordDetail` struct (value, timestamp, coordinate, altitude, locationName, recordType, timeFrame)
   - Helper methods: `getRecord(type:timeFrame:)` and `setRecord(type:timeFrame:record:)` for accessing records
   - `updateRecords(with:reverseGeocodedName:)` is the main entry point
     - Automatically performs reverse geocoding if locationName not provided
     - Compares new location against current records using threshold deltas from SettingsManager
     - Creates new records and saves to Core Data via RecordHistoryManager
     - Sends notifications based on timeframe-specific settings (monthly, yearly, all-time)
   - `loadRecordsFromHistory()` - Called on init to restore records from Core Data
   - **Important:** Altitude records store raw meters in Core Data but display conversions based on unit system

3. **SettingsManager** (`SettingsManager.swift`)
   - Singleton: `SettingsManager.shared`
   - Persists to `UserDefaults`
   - Key settings:
     - `notifyOnMonthlyRecords: Bool` - Whether to send notifications for monthly records (default: false)
     - `notifyOnYearlyRecords: Bool` - Whether to send notifications for yearly records (default: false)
     - `notifyOnAllTimeRecords: Bool` - Whether to send notifications for all-time records (default: true)
     - `minLatitudeDelta`, `minLongitudeDelta` - Threshold in degrees for directional records
     - `minAltitudeDeltaFeet` - Threshold for altitude records (stored as feet, converted to meters)
     - `homeCoordinate: CLLocationCoordinate2D?` - For "Furthest from Home" calculations
     - `unitSystem: UnitSystem` - `.metric` or `.imperial` for display
   - Use `saveSettings()` after modifying properties

4. **RecordHistoryManager** (`RecordHistoryManager.swift`)
   - Singleton: `RecordHistoryManager.shared`
   - Manages Core Data persistence
   - `addRecord(recordType:detail:)` - Saves record to Core Data
   - `clearHistory()` - Batch deletes all entries and resets RecordManager in-memory records

5. **PersistenceController** (`PersistenceController.swift`)
   - Singleton: `PersistenceController.shared`
   - Wraps `NSPersistentContainer` for Core Data model "GeoRecordsModel"
   - Injected into environment at app root

### Core Data Model

**Entity:** `RecordHistoryEntry` (class auto-generated by Xcode)
- `id: UUID`
- `timestamp: Date`
- `recordType: String` - e.g., "Furthest North"
- `value: Double` - The extreme value (latitude, longitude, altitude meters, or distance feet)
- `latitude: Double`, `longitude: Double`
- `altitude: Double` - Always stored in meters
- `locationName: String?` - Reverse geocoded name

### Views

- **ContentView** - Root view with TabView (Records, History, Settings)
  - Handles deep links from notifications via `DeepLinkManager.shared.$recordType`
  - Deep link navigation triggers `RecordDetailView` for the tapped record
- **RecordsView** - Displays all 7 current records using `RecordCard` components
  - Each card links to `RecordDetailView`
- **HistoryView** - Uses `@FetchRequest` to display all `RecordHistoryEntry` sorted by timestamp
  - Links to `HistoryDetailView` for each entry
- **SettingsView** - Edits `SettingsManager` properties and sets home location via `HomePickerView`
- **RecordDetailView** - Shows record details and map
- **HistoryDetailView** - Shows history entry details and map
- **HomePickerView** - Map picker for setting home coordinate

### Notification System

- **NotificationDelegate** (`GeoRecords.swift`) - Handles foreground presentation and tap responses
- **DeepLinkManager** - Simple `@Published var recordType: String?` to trigger navigation
- Notification payload includes `userInfo["recordType"]` for deep linking
- Permissions requested in `GeoRecords` app initializer via `requestNotificationPermissions()`

## Key Implementation Details

### Unit System Conversions

- **Altitude:** Core Data stores meters, but `RecordDetail.value` for "Furthest Up/Down" also stores meters
  - Display conversion happens in views: `value * 3.28084` for imperial
- **Distance from Home:** Core Data stores feet in the `value` field
  - Display: feet → miles (imperial) or feet/3.28084 → meters/km (metric)
- **Lat/Lon:** Always stored and displayed as degrees

### Record Threshold Logic

Records are updated only if the delta exceeds the configured threshold:
- North: `newLat - currentLat > minLatitudeDelta`
- South: `currentLat - newLat > minLatitudeDelta`
- East: `newLon - currentLon > minLongitudeDelta`
- West: `currentLon - newLon > minLongitudeDelta`
- Up: `newAlt - currentAlt > minAltitudeDeltaFeet * 0.3048` (converted to meters)
- Down: `currentAlt - newAlt > minAltitudeDeltaFeet * 0.3048`
- Furthest from Home: `newDistance > currentDistance` (any increase)

### Background Location

- Uses `startMonitoringSignificantLocationChanges()` for true background operation
- Triggers updates when device moves approximately 500 meters
- No timers needed - iOS handles scheduling automatically
- Battery efficient and works indefinitely in background
- Requires "Always" authorization (requested in init)
- Info.plist includes `UIBackgroundModes: ["location"]` and location usage descriptions
- App continues tracking records even when completely backgrounded or terminated by system

## Common Patterns

### Modifying Settings

```swift
let settings = SettingsManager.shared
settings.minLatitudeDelta = 0.5 // Degrees
settings.unitSystem = .metric
settings.saveSettings()
```

### Adding a New Record

RecordManager automatically handles this when location updates, but manual testing:

```swift
RecordManager.shared.updateRecords(with: testLocation, reverseGeocodedName: "Test Location")
```

### Accessing Current Records

```swift
// Access a specific timeframe record
if let record = RecordManager.shared.furthestNorthAllTime {
    print("Furthest north: \(record.value)° at \(record.locationName ?? "Unknown")")
}

// Or use the helper method
if let record = RecordManager.shared.getRecord(type: "Furthest North", timeFrame: .allTime) {
    print("Furthest north: \(record.value)° at \(record.locationName ?? "Unknown")")
}
```

### Core Data Queries

History view uses `@FetchRequest`. For custom queries:

```swift
let context = PersistenceController.shared.container.viewContext
let request: NSFetchRequest<RecordHistoryEntry> = RecordHistoryEntry.fetchRequest()
request.predicate = NSPredicate(format: "recordType == %@", "Furthest North")
request.sortDescriptors = [NSSortDescriptor(key: "value", ascending: false)]
let results = try context.fetch(request)
```

## Development Considerations

- All managers are singletons accessed via `.shared`
- Location updates trigger automatic record checks - no manual polling needed
- Significant location changes (~500m) provide good balance for geographical record tracking
- UI updates automatically via `@Published` properties and SwiftUI bindings
- Always test with real device for location and background behavior
- Reverse geocoding happens asynchronously - `updateRecords` calls itself recursively with the result
- Background tracking works even after app termination - iOS will relaunch the app to handle location updates
